# Week 07 — Git, GitHub Actions, pytest en code review

**8–12 uur | Eindresultaat:** PR of patch, drie relevante tests en groene CI.

## Begrippen
1. commits, branches en pull requests
2. unit, integration en regressietests
3. pytest en fixtures
4. GitHub Actions workflow en CI-fouten

## Leerbronnen
- [GitHub Actions Python](https://docs.github.com/en/actions/tutorials/build-and-test-code/python)
- [pytest](https://docs.pytest.org/en/stable/)

## Dagplanner
| Dag | Activiteit |
|---|---|
| Ma — 1,5u | Lees eerste bron, schrijf in 10 zinnen wat je begreep |
| Di — 1,5u | Herhaal theorie en doe twee begeleide voorbeelden |

## Lab / praktijkopdracht
Maak een feature-branch; schrijf eerst een falende pytest, voeg een kleine endpoint-feature toe, maak een PR en controleer CI. Reproduceer één bug uit een testmelding.

## Definition of Done
- [ ] Labopdracht uitgevoerd.
- [ ] Bewijs gecommit of gelinkt: PR of patch, drie relevante tests en groene CI.
- [ ] Mijn eigen architectuur-/beslissingsuitleg toegevoegd.
- [ ] Belangrijkste fout en aanpak genoteerd in het learning journal.
- [ ] Weekquiz beantwoord zonder AI.

## Vijf interviewvragen
1. Waarom een PR?
2. Wat test een unit test?
3. Waarom CI?
4. Wat is een regressie?
5. Wanneer is een test onbetrouwbaar?

## Gate
> Je kunt zelfstandig een testfout interpreteren en oplossen.

## Stretch
Ontwerp een edge case waarin jouw oplossing faalt. Beschrijf impact voor gebruiker, beheerder én bedrijf. Laat AI de aannames bekritiseren nadat je het zelf hebt uitgewerkt.

## Mentoropdracht
'Wees mijn strenge docent voor **Git, GitHub Actions, pytest en code review**. Stel vragen één voor één, geef hints maar nooit direct de volledige oplossing. Evalueer wat ik onafhankelijk begrijp en maak een herhalingsoefening.'
